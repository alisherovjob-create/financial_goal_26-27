Этот файл подготовлен для существующего проекта Apps Script, привязанного к таблице.
Автоматическая публикация и удаление строк в вашей таблице не выполнялись.

1. Сохраните резервную копию текущего кода Apps Script.
2. Сохраните существующее объявление `const SHEET_NAME = ...` с вашим именем листа.
   Замените существующие функции содержимым `Sync.gs` (не оставляйте вторые doGet/doPost).
   Столбцы A:E должны быть Date, Category, Planned, Actual, UpdatedAt.
3. В настройках Google-таблицы проверьте часовой пояс: Москва (Europe/Moscow).
   Сервер использует часовой пояс таблицы, а не проекта скрипта.
4. Развернуть → Управление развертываниями → выбрать действующее → Изменить →
   Новая версия → Развернуть. Существующий URL /exec сохранится.
5. Один раз выполните `deduplicateEntries` из редактора Apps Script.
   Функция сначала создаёт копию всего листа Entries_backup_<время>, затем удаляет
   старые дубли. Остаётся запись с самым поздним UpdatedAt; при равенстве — нижняя
   строка. Суммы дублей не складываются. GET сам ничего не удаляет.
6. Откройте /exec: Date должен иметь вид 2026-09-25, UpdatedAt — полный ISO timestamp.
7. После отдельной публикации исправленного index.html проверьте страницу в инкогнито.
   Измените одну сумму два раза: число строк для этой даты и категории не должно расти.

POST ищет строку по нормализованной дате и категории под ScriptLock. До ручной очистки
старых дублей он обновляет все совпадающие строки, не создавая новых. После очистки
на пару остаётся одна строка. Повтор после сетевой ошибки обновляет ту же строку.

Документация Google:
- https://developers.google.com/apps-script/concepts/deployments
- https://developers.google.com/apps-script/reference/lock/lock-service

## Вкладка «Расходы по статьям»

Загрузите вместе `index.html`, `expenses.js`, `expenses.css` и `design.css`. Обновите содержимое
существующего проекта Apps Script кодом `Sync.gs`, сохранив ваше объявление
`const SHEET_NAME = ...`, затем обновите действующее развёртывание новой версией
(пункт 4 выше). Без этого вкладка покажет просьбу обновить Apps Script и не будет
считать расход сохранённым.

При первом успешном расходе автоматически создаётся отдельный лист `Expenses`
со столбцами `Id, Category, Amount, Comment, CreatedAt`. Лист накоплений не меняется.
GET `?action=expenses` читает историю, POST `action: addExpense` добавляет запись.
Время задаётся сервером; на сайте отображается по Москве. Суммы — целые рубли.
Идентификатор расхода обеспечивает безопасный повтор после сетевой ошибки.
Запись расходов защищена блокировкой от одновременных повторных запросов.
Расходы сверх остатка разрешены; доступный остаток может быть отрицательным.

Накопления соответствуют выбранному периоду основной вкладки. История расходов
по статье общая и сохраняется при смене периода и сбросе накоплений. При уменьшении
накоплений ниже уже потраченной суммы остаток отображается отрицательным.
Новые расходы разрешены и при нулевом или отрицательном остатке. Правки листа Expenses загружаются при открытии вкладки и по
кнопке «Синхронизировать расходы». Во время отправки кнопка блокируется.
После неопределённого результата повторите расход с исходными суммой и комментарием:
изменять его до подтверждения нельзя, чтобы не создать второй расход.

Публикация кода в Google и запись в настоящую таблицу из рабочего окружения
не выполнялись. Проверки используют подменённый API, а не ваши данные.
