Проверка: Python 3, пакет `playwright`, установленный Google Chrome.
Запуск из корня проекта: `python3 tests/test_sync.py`.
Тест открывает исходный HTML в Chrome и подменяет только API; настоящую таблицу не изменяет.
Проверяет загрузку, debounce, POST, ноль, перезагрузку, офлайн-кэш, защиту очереди,
повторную отправку, редактирование во время POST, HTTP/JSON-ошибки и ошибки JavaScript.

Ручная проверка:
1. Откройте financial_tracker_365.html. Дождитесь «Сохранено ✓».
2. Измените факт, подождите около секунды и завершения запроса. Проверьте строку
   в Google Sheets по дате и категории; обновите страницу.
3. Очистите поле: в таблице должно сохраниться 0, после обновления — отображаться 0.
4. В DevTools → Network включите Offline, введите сумму, обновите страницу.
   Сумма должна остаться. Верните Online, нажмите «Синхронизировать», проверьте таблицу.
5. Измените Actual непосредственно в Sheets, нажмите «Синхронизировать»:
   значение загрузится, если для этой ячейки нет локального несохранённого изменения.

Период и ручное закрытие выплаты остаются локальными: API не содержит этих полей.
Старые локальные суммы при первом запуске считаются ещё не синхронизированными.
CSV и сброс факта также ставят изменения в очередь; сброс отправляет нули.
Очередь повторяется после восстановления сети и каждые 30 секунд при её наличии.
Для гарантированного результата дождитесь «Сохранено ✓» перед закрытием вкладки;
неотправленные данные остаются в localStorage до следующего открытия.
